## 一、任务与范围确认（别跳过）

用户原话：「复制一份商品分组，比如学习文具复制成学习文具（兑换），是否在网店显示选择否」。

「比如」覆盖到哪？1 个 / 9 个一级 / 整树 118 节点，写入量差两个数量级，**必须问清再动手**。本次确认口径：

- 范围 = **整树**：9 个一级 + 109 个二级；
- 二级也加（兑换）后缀（「铅笔」→「铅笔（兑换）」），挂在对应的（兑换）一级下；
- 全部副本 `isShow=false`（是否在网店显示 = 否）；
- 排序 `sort`、分组图片 `imageUrl` 按源分组复制；原分组零改动。

## 二、建组入参实测（最重要的一条）

`addGoodsClassify` 的入参形状**按层级不同**，docs/10 旧示例给的是二级口径，照抄到一级会报错：

```
POST /api3/mall/goods/classify/addGoodsClassify
```

| | 一级分组（UI 真实 payload） | 二级分组 |
|---|---|---|
| `name` | ✅ | ✅ |
| `classifyLevel` | `1` | `2` |
| `parentId` | **不传**（传 `0` 会报错，见下） | ✅ 必传父级 classifyId |
| `isShow` | ✅ | ✅ |
| `sort` / `imageUrl` | 可选（复制语义时带上） | 可选 |
| `basicInfo` / `solutionType` / `i18n` / `extendInfo` | ✅ 通用壳 | ✅ 通用壳 |

**血泪点**：一级分组 body 里传 `parentId: 0`（或任何多余字段当 null）直接报
`{"errcode":"001450020000001","errmsg":"入参存在空值"}` ——「空值」指的是**你多传的字段**，不是缺字段。
docs/10 旧文「一级填 0」的说法**已修正**，一级就是**整个字段不出现**。

### UI 拦截取证法（零写入拿到真实 payload）

API 直发连续报「入参存在空值」、猜不出来缺哪个/多哪个时，**别再猜**，去拦 UI 的真实请求：

1. 打开目标页面，把「新建/编辑」弹窗照常填好；
2. `page.route('**/api3/**')` 里命中目标写接口 → **记录 `postData()` 后 `route.abort()`**（请求不落线上）；
3. 点「确定」→ payload 已在手，与自己发的 body 逐字段 diff。

本次就是靠这招 5 分钟定位（vs 变体穷举 5 轮全失败）。拦截脚本：`scripts/44-capture-ui-payload.js`。
同类先例：docs/14 排序写接口 `updatePointGoodsSort` 也是拦 UI 拿到的。

## 三、执行流水（七步法实例）

| 步骤 | 产出 | 说明 |
|---|---|---|
| ① 改前快照 | `商品分组_改前快照_*.json` | 全量树，含 STATIC 字段基线 |
| ② 工作条目 | 计划表：对象/现状/目标/依据/风险/验收 | 范围歧义单独列「待确认」，问完再动 |
| ③ 最小改动 | 只调 `addGoodsClassify`，其余写接口路由层 abort | 写白名单只有 2~3 个端点 |
| ④ 小样 | 1 个二级（铅笔（兑换））建完立即 `queryClassifyDetail` 独立复核 | PASS 才放开批量 |
| ⑤ 批量 | 117 个，分批 ≤25 + 批间 sleep，首败即停 | 本次 0 失败 |
| ⑥ 多次 review | 改后快照 diff（STATIC 零变化）+ 逐一级子级数/命名核对 + 独立接口抽查 | 三层验收缺一不可 |
| ⑦ 总结 | 本文 + docs/09 新增 4 坑 + 脚本入库 43~46 | |

验收口径（STATIC / VOLATILE 分层沿用 docs/14）：

- **STATIC**（`name/parentId/classifyLevel/isShow/isHot/sort/imageUrl`）：既有节点必须零变化，变了即失败；
- **VOLATILE**（`countGoodsNum`、子级数）：只报告不判失败，**绝不顺手改**。

## 四、本次踩坑（4 条，已入 docs/09 #27~#30）

1. **一级传 `parentId: 0` → 「入参存在空值」**（详见上节）；
2. **复制脚本的源清单没冻结** → 把刚建好的「学习文具（兑换）」当源又套一层，造出空组「学习文具（兑换）（兑换）」。
   **铁律：源清单 = 作业开始前的基线快照，且先滤掉名字已带目标后缀的节点。** `scripts/45` 已内置该过滤；
3. **写守卫黑名单子串误伤**：`'deleteGoods'` 是 `'deleteGoodsClassify'` 的子串，守卫把本次唯一计划写操作自己拦了。
   **黑名单一律精确到端点名，不用裸子串**；
4. **节点数变多后页面换查询接口**：分组节点 >200 后页面不再发 `queryAllClassifyListForManagement`，改发 `queryClassifyListWithPageForManagement`（管理分类的分页查询），脚本只认前者会「未捕获到模板」。
   **模板捕获放宽到任意 `classify/query*` 请求 + 重载重试**，树读取仍调全量接口（实测仍可直调）。

## 五、纠错实录（自造越界产物的删除流程）

越界产物是自己脚本造的，删除同样走纪律（删除属高危动作，先经用户确认）：

1. 删前快照 + 身份核对（名字、`parentId`、**子级数=0**）+ `countChildClassifyByParentClassifyId` 双确认空组（级联风险为零）；
2. `deleteGoodsClassify` 只发一次，目标 id 显式写死；
3. 删后全量比对：删除集**恰好 = {目标 id}**、零新增、零 STATIC 修改、无双后缀残留。

结果：`pass=true`。结论——**纠错动作也是写操作，同样小样 + 回读**。

## 六、交付物与复用脚本

| 脚本 | 用途 | 关键点 |
|---|---|---|
| `scripts/43-export-all-readonly.js` | 商品分组 / 积分商城 / 商品列表+详情 三块全量只读采集 | 写接口路由层 abort；商品列表 pageSize=20；详情带完整 `filterOption` |
| `scripts/44-capture-ui-payload.js` | UI 拦截取证：填表 → 记录真实 payload → abort | 零写入；名称输入框认「填写分组名称」别认搜索框 |
| `scripts/45-copy-classify-tree.js` | 整树复制：X → X+后缀，isShow 可控 | **源清单冻结 + 自动滤掉已带后缀节点**；幂等（同名同父跳过）；形状 A/B/C 自动降级；小样 + 三查内置 |
| `scripts/46-delete-classify-verified.js` | 验证式删除单个分组 | 空组双确认 → 单次删除 → 全量比对恰好少一个 |

跑法（凭据走环境变量 / config.local.js，不落盘）：

```bash
node scripts/43-export-all-readonly.js              # 三块只读备份
node scripts/44-capture-ui-payload.js               # 建组入参取证（零写入）
node scripts/45-copy-classify-tree.js --suffix=（兑换） --show=false   # 整树复制
node scripts/46-delete-classify-verified.js <classifyId> <期望名称>    # 验证式删除
```
