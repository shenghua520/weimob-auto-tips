# 24 · 同名多规格商品匹配与独立复核口径假阳性实战

> 场景：学习文具 seq56 两行商品名相近、规格同为「无」，上一轮被判为冲突跳过；用户人工确认后补同步。
> 两条核心教训：**按首行名称归一化会把不同商品误判成一对多冲突**；**独立复核的字段口径不一致会造出假 FAIL**。

## 一、问题现象

seq56 表格两行（Excel145/146）：

| Excel 行 | 编码 | 名称 | Q 售价 | S 组合价 | T 豆 | 微盟 outerGoodsCode |
|---|---|---|---|---|---|---|
| 145 | APYMU268 | 感悟生活本白写生**4K 20页**素描 | 8.6 | 5.80 | 28 | 3057 |
| 146 | APYMV268 | 感悟生活本白写生**110g 8K 20页** | 4.8 | 2.00 | 28 | 3056 |

上一轮 133 计划把两行按首行名称归一化（去空格/去「【兑换】」）后归到同一个商品组 3057，
两行价格不同（8.6 vs 4.8）→ 判成「一对多 price/point 冲突」→ **整组跳过，微盟一直停在旧价 7.9/4.3**。
并在表格 U144/U145 留了「待人工确认」备注。用户核对后说「55、56 那两个我看了没错，同步到微盟」。

## 二、根因：名称归一化不是商品主键

- 两个商品名称前缀相同（「感悟生活本白写生」），但规格段不同（4K vs 8K），对应**不同的 outerGoodsCode**（3057 / 3056）。
- 上一轮的匹配优先级是「编码 → 规格 → 首行名称归一化」，名称归一化兜底时把不同商品吞成一个组。
- 正确做法：表格行的**内部编码（D 列）**虽不等于微盟 outerGoodsCode（APYMU268 vs 3057），
  但可以用「名称 + 规格关键词」精确定位到**两个不同 goodsId**，再按下表锁定：

```
4K 20页   → 3057 → orig 161456347100397 / exch 161785315100397
110g 8K   → 3056 → orig 161456494100397 / exch 161785682100397
```

**经验**：判「一对多冲突」之前，先确认匹配到的候选是不是真的同一个商品——
用 outerGoodsCode / SKU 条码 / 规格关键词做二次校验，别让名称归一化把不同商品合并。

## 四、独立复核里的两次假阳性

### 1. 字符串 vs 数值

156 初版拿台账 `target[0]=28` 与计划 `target[0]=28.0` 做字符串比较 → 报 2 处差异。
**修复**：一律 `float()` 归一后再比（`abs(a-b) < 0.001`）。

### 2. 嵌套字段提顶导致的口径错位

157 初版拿原始详情的 `d.classifyId` 比快照里的 `g.classifyId` → 现网是 `undefined`，报 guard FAIL。
根因：131 快照脚本把 `pointClassifyInfo.pointClassifyId` 提到了顶层 `classifyId`，
而原始详情接口仍把 classifyId 放在 `pointClassifyInfo` 里——**这正是 MEMORY D 节记过的坑，又踩了一次**。
**修复**：`d.classifyId ?? (d.pointClassifyInfo || {}).pointClassifyId`，双口径兼容。

> 两条假阳性都产生在「独立复核」环节，若不看具体字段就信 FAIL 结论，可能触发错误回滚。
> **复核报 FAIL 时第一步是打印差异字段，不是立即回滚。**

## 五、Takeaway

1. **名称归一化作兜底匹配是危险的**：前缀相同、规格不同的商品会被合并，进而误判成冲突而整组跳过。
   遇到冲突先查候选的 outerGoodsCode / 规格关键词，确认是不是真同一商品。
2. **被跳过的行必须留可见痕迹**：备注「待人工确认」起了作用——用户看到后主动确认，补写了漏掉的商品。
3. **复核报 FAIL 先诊断口径**：`28` vs `28.0`、`classifyId` 顶层 vs 嵌套，都是假阳性常见来源；
   打印具体字段再决定是否回滚。
4. **guard 字段的完整照录仍然有效**：153/155 用 `mkBody` 从写前详情逐字段带回，
   写后 `classifyId/priceType/goodsLimitNum/sort/兑换时段/visibleInNonExchangeTime` 全部未变。
5. **清空备注用 `clear_range_cells`**，不是写空串；写回文本用 `value_type=STRING` + `string_value`，
   `value` 字段会被静默忽略（docs/23 已记，本轮未再踩）。
