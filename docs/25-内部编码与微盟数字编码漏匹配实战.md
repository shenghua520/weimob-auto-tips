# 25 · 表格内部编码 vs 微盟数字编码：漏匹配导致"微盟价格没跟上"

> 核心教训：**"名称+编码零命中"不等于"微盟没有这个商品"**。表格用商品内部编码（如 `APS906T1`），
> 微盟 `outerGoodsCode` 用纯数字（`2945`），两套编码体系不通；只按编码匹配会把真实存在的商品判成"零命中"跳过，
> 结果表格价格改了、微盟没跟，对账还因为"目标价取自跳过前的旧计划"而显示全对——三重自证闭环掩盖了漏写。

## 一、问题现象

用户反馈："书包款削笔机价格就不一样。" 表格 Excel52「1个（颜色随机）」规格 Q=16.7，微盟售价 15.2。
但上一轮 133 计划把 seq20/22/23/25/26/27 全部归入 skipped，理由"微盟零命中（名称+编码）"，
且随后的 150/160 对账都显示"售价 457 SKU 差异 0"——对账和现实矛盾。

## 二、根因：两套编码体系 + 对账自证

1. **表格编码 ≠ 微盟编码**：表格 E 列是商品内部编码（`APS906T1` / `APS906T2` / `APS912D4` / `APSN1298` / `APSN1297` / `APS906J5`），
   微盟 `outerGoodsCode` 是纯数字（`2945` / `2944` / `2952` / `2949` / `2947` / `2943`）。
   按编码匹配必然零命中，但商品其实存在（原版 + 兑换版各一）。
2. **对账用了错误基准**：150 脚本的"目标价"取自 133 计划（跳过这些商品 → 根本没有目标），
   160 脚本虽改用表格现价，但目标集合仍来自 133 的 `priceWrites`（同样不含这些商品）——
   两者都不检查"表格有价但计划里没有目标"的行，所以双双 PASS。**这是典型的"用写入计划当验收基准"的自证陷阱。**

## 三、正确做法

- **匹配兜底必须按名称归一化再验规格**：`norm(title)` 去空格 / 去「（兑换）」后缀后能命中微盟标题
  （表格「APS906T1 书包款削笔机」→ 微盟「书包款削笔机」）。命中后再用规格值 / 商品分组二次校验。
- **表格标"未录入微盟"也可能是历史遗留**：不要据此断言微盟无此商品，先按名称搜一遍微盟全量。
- **对账基准必须是"表格全部有价行"**，而不是"计划里的写入目标"；
  凡表格有 Q/S/T 但微盟命中商品却不在计划里的，一律列为"漏写可疑"单独报告。

## 五、Takeaway

1. **零命中必须二次验证**：按编码零命中后，务必用名称归一化 + 规格再搜一遍；"表格内部编码体系"与"微盟数字编码体系"天然不通。
2. **对账基准不能取自写入计划**：计划里没有的行 = 根本没被检查的行。全量对账要从"表格全部有价行"出发，
   反查微盟是否命中、命中是否写过。
3. **表格状态是参考不是事实**：标"未录入微盟"的行可能微盟实际存在（历史遗留 / 后来补录），以微盟实况为准。
4. **整盒规格无对应 SKU 就跳过**：微盟单 SKU 商品只对应表格「1个」规格，不要强行把整盒价写进单 SKU。
