# 自查 01 · 后台内部接口（非官方）

> ⚠️ **这些接口不是微盟官方开放能力。**
> 全部从后台浏览器流量里逆推得到，**没有文档、没有版本、没有兼容承诺**，随前端发版随时可能改。
>
> - 用于：只读巡查、后台没开放给 WOS 的边缘功能、一次性数据清理
> - 不要用于：长期运行的生产集成、定时任务、对外服务
> - 官方能力请见 [官方-01 WOS](官方-01-WOS开放平台.md) / [官方-02 iPaaS](官方-02-iPaaS私域网关.md)

**规模**：已探明 **38 个**（9 个域）｜权限码 **725 条**（28 个产品线）｜实测 2026-10-25 ~ 10-26

---

## 一、通用约定

```
POST https://master.weimob.com/api3/<域>/<资源>/<动作>
Content-Type: application/json

必备请求头（缺任一个直接 fail auth）：
  authorization   登录票据（从页面 XHR 抄）
  apiclient       客户端标识
  weimob-bosid    商户 ID
  referer         来源页
  apipath         仅 iPaaS 网关需要，用来区分功能
```

所有接口共用 `basicInfo` 骨架（`tcode / bosId / vid / vidType / productId / productVersionId / productInstanceId / statusCode / i18n / extendInfo`），
从任意页面 XHR 抄一份当模板即可，见 [00 章](00-概览与快速开始.md)。

**`errcode` 类型不统一**：商品域是字符串 `"0"`，素材域是数字 `0`。判断写 `err === 0 || err === '0'`。

## 九、自查接口是怎么挖出来的

### ① 抓页面真实请求（最准）

```js
page.on('request', r => {
  if (!r.url().includes('/api3/')) return;
  if (!(r.postData() || '').length) return;
  record({ url: r.url(), body: r.postData(), headers: r.headers() });
});
```

`scripts/00-sniff-api.js` 就是这个 —— 手动点一遍模块，自动产出台账（含完整 body + 头）。
这是唯一能同时拿到"完整参数 + 完整鉴权头"的方式。

### ② 权限码反推

```
mpmaterial#mpmaterial.material.store   → 店铺素材页 → material/center/material/getMaterialList
mpcms#app.design.editor                → 装修编辑器 → mp-decoration/biz/editor/queryEditor
```

路由层级与接口层级高度一致，能快速缩范围。

### ③ 命名探测（最后手段）

```
POST api3/mall/goods/classify/addGoodsClassify   → 200 {"errmsg":"参数: name 为空"}   ✅ 存在
POST api3/mall/goods/classify/saveGoodsClassify  → 404                              ⛔ 不存在
```

好处：错误信息直接告诉你缺哪个字段。坏处：命中率低 —— `deleteMaterial` 猜了 3 个名字全 404。

## 十、未探明的部分

| 模块 | 为什么没探 |
|---|---|
| 订单 / 售后 / 退款 / 发货 | **建议直接走 WOS**，不必逆推 |
| 发票开具 / 提现 | 涉及资金，风险高 |
| 营销活动创建 / 发券 | **建议直接走 WOS**（`marketing` 域） |
| 账号权限 / 审核 | 改权限风险高 |

> 这一类本来就是 WOS 的强项，**没必要逆推**。只在 WOS 没覆盖时才继续挖后台接口。
