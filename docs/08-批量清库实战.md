# 08 · 批量清库实战（必读）

> 任务：把商户后台的 **180 个商品**全部删除、**素材库**只留还在用的、库存清空。
> 结果：商品 180 → 0，素材 5552 → 57，库存留下 12 条孤儿行（见第 6 节）。
> 全程零误删，所有对象都有回滚备份。

## 0. 顺序决定成败

```
① 只读盘点数量
② 全量备份（JSON + CSV）
③ 【库存清零】           ← 必须在删商品之前
④ 算出素材引用关系
⑤ 删商品（20 条/批）
⑥ 删未使用素材（20 条/批）
⑦ 双路径复核
```

**本次是倒着做的**（先删商品才想清库存），所以踩了孤儿库存的坑。
库存清零一定要在删商品之前——SKU 还在的时候，库存调整才有对象可落。

## 1. 只读盘点（不要省）

```bash
# 商品
POST /api3/mall/goods/queryGoodsListWithPageForManagement  → data.totalCount = 180
# 素材
POST /api3/material/center/material/getMaterialList        → data.totalCount = 5553
# 页面
POST /api3/cms/mgr/page/query                              → totalCount = 5
```

三个数字先记下来，后面每一步都要跟它对齐。

```js
fs.writeFileSync(p, '\uFEFF' + csv, 'utf8');
```

## 3. 算素材引用（删前必做）

跳过这步 = 首页白图。

```text

→ 素材库 url 命中 = 保留（52 条）；未命中 = 可删（5501 条）
```

详见 [04 · 素材库](04-素材库-material.md) 第 3 节。

## 4. 删商品

```js
for (let round = 0; round < 15; round++) {
  const ids = (await listAll()).map(g => g.goodsId);
  if (!ids.length) break;
  for (let i = 0; i < ids.length; i += 20) {
    const r = await post('/api3/mall/goods/deleteGoods', { ...basic, goodsIdList: ids.slice(i, i + 20) });
    // 失败则拆成单条重试，定位不可删的
    await sleep(1000);
  }
  const after = await listAll();
  if (after.length >= ids.length) break;   // 数量不降 → 停，别硬跑
}
```

实测过程：

```
[第1轮] 剩余 180（先手动删了 20 条 → 160）
   批1..批8: 各 20 个 → OK
   本轮后剩余 38
[第2轮] 剩余 34
最终 0
```

> 数字会小幅抖动（38 → 34 → 37），因为删除是异步落库 + 列表有缓存。
> **判断标准是"趋势向下"而不是"每批精确 −20"**。

## 5. 删素材

```js
// 按 createUid + materialType 分组，同组才能批量
for (const [k, items] of groups) {
  for (let i = 0; i < items.length; i += 20) {
    const batch = items.slice(i, i + 20);
    const r = await post('/api3/material/center/material/deleteMaterial', {
      ...basic,
      materialIdList: batch.map(x => x.id),
      materialIds:    batch.map(x => x.id),
      materialType: batch[0].materialType,
      updateUid:    batch[0].createUid,    // ← 必须是 createUid
    });
    if (r.errcode !== 0 && r.errcode !== '0') { /* 拆单逐条重试 */ }
    await sleep(200);
  }
}
```

实测：5501 条 / 2 分 18 秒 / 成功率 100%。

## 6. 库存：本次没做成的那一步

| 项 | 结果 |
|---|---|
| 入库单 / 出库单 | 0 ✅ |
| 库存查询 | 12 条孤儿 SKU（关联商品 0），实物库存 103/113/110/200 |
| 库存调整 | 提交 `createAsyncStockTask` 全部 `result:true`，**数值未变** |
| 结论 | 商品已删 → SKU 不存在 → 任务无落点。只能客服清档 |

**教训：库存清零要在删商品之前。** 顺序错了就回不去（商品已经没了）。

## 7. 复核（两条独立路径）

```bash
# 商品
接口 totalCount = 0      且   页面 innerText「共 0 条」
# 素材
接口 totalCount = 57     且   保留清单 52 条的 url 在页面上能正常显示
# 库存
入库单/出库单 0 条        （孤儿行单独记录，接受）
```

## 8. 回滚怎么做

| 对象 | 能不能回滚 | 怎么回 |
|---|---|---|
| 商品 | ⚠️ 不能自动回滚 | 按 CSV 的 `goodsId`/名称/价格/库存逐条重建；订单快照不受影响 |
| 素材 | ✅ 可恢复 | CDN 原图**没被物理删除**，按备份 CSV 里的 URL 重新上传即可 |
| 库存 | ❌ | 孤儿行无法回滚也无法清零 |

> 这就是为什么素材删除"相对安全"（链接还在），商品删除"最危险"（只能重建）。

## 9. 用时参考

| 阶段 | 耗时 |
|---|---|
| 盘点 + 备份 | ~4 分钟 |
| 素材引用分析（开 5 个编辑器） | ~1.5 分钟 |
| 删 180 商品 | ~40 秒 |
| 删 5501 素材 | 2 分 18 秒 |
