# 00 · 概览与快速开始

## 1. 站点长什么样

微盟商户后台不是"一个后台"，是**一个壳 + 十几个微前端产品**：

```
https://master.weimob.com/bos/products/<productCode>/<BOS_ID>/<KEY>/<路由...>
                                       ↑            ↑        ↑
                                    产品线代码     商户ID   门店/组织 key
```

- 顶部导航（店铺 / 商城 / CRM / 员工 / 供应链 / 店务 / 收银 / 分销 / 营销 / 推广 / 数据 / 客服 / CDP / 内容 / 应用）
  每切换一个，URL 里的 `productCode` 就变一次，前端重新 mount 一个子应用。
- 侧边栏菜单、页面内容**经常在 iframe 里**，主文档 `document.body.innerText` 抓不到正文。

### 常用 productCode 对照

| 顶部导航 | productCode 示例 | 管什么 |
|---|---|---|
| 店铺 | `home` / `mpcms` / `mpfinance` / `mprisk` | 装修、财务中心、素材、消息、账号权限、风控 |
| 商城 | `ecOrder` / `ecGoods` / `ecGoodsmanage` / `ecSetting` / `ecStore` | 订单、售后、库存、商品、商城设置 |
| CRM | `onecrm` / `onecrm01` | 客户360、会员、券码、积分/储值（资产管理） |
| 员工 | `staff` | 员工、排班、作品案例 |
| 供应链 | `wosheading` / `wosheadingreport` | 总部商品、采购、财务对账 |
| 店务 | `wosheadingsop` | 门店、价格、店务、门店订单 |
| 收银 | `wosheadingpos` | POS 参数、设备、支付、日志 |
| 分销 | `ecTweeter` | 微客、分销商品 |
| 营销 | `mkmarketing` | 营销中心、营销日历 |
| 数据 | `sente` | 数据看板、自助取数 |
| 客服 | `im` | 客服工作台、会话、质检 |
| 内容 | `mkPromotionLive` | 直播、文章 |

> 完整 13 个模块 / 428 个功能入口见 `scripts/02-build-feature-map.js` 生成的地图。

## 2. 五分钟上手

```bash
# 0) 依赖：node 18+，playwright-core（用 WorkBuddy 自带的也行）
#    浏览器用已缓存的 chromium，显式指定路径，避免版本不匹配
# 1) 把凭证写进 config.local.js（已 gitignore）
cat > config.local.js <<'EOF'
module.exports = {
  BASE: 'https://master.weimob.com',
  BOS_ID: '<BOS_ID>',
  KEY: '<KEY>',            // URL 里 bosId 后面那串
  VID: '<VID>',
  CHROME: 'C:/Users/<you>/AppData/Local/ms-playwright/chromium-1243/chrome-win64/chrome.exe',
  PROFILE: './.profile',   // 持久化登录态
};
EOF

# 2) 登录一次（持久化后免登录）
node scripts/lib/common.js login

# 3) 抓菜单树
node scripts/01-sniff-menu.js

# 4) 生成可检索功能地图
node scripts/02-build-feature-map.js
```

## 3. 通用请求约定

所有业务接口都是 **POST + JSON**，body 有固定骨架：

```jsonc
{
  "basicInfo": {
    "tcode": "weimob",
    "merchantId": "<MERCHANT_ID>",
    "bosId": "<BOS_ID>",
    "vid": "<VID>",
    "vidType": 2,
    "vidTypeName": "品牌",
    "vidTypes": [2],
    "vidPath": "-<VID>-",
    "isRootVid": true,
    "productId": 145,              // 商品/订单域=145，CRM 域=146
    "productVersionId": "<VERSION>",
    "productInstanceId": <INSTANCE>,
    "statusCode": "in_use",
    "vidName": "<商户名>"
  },
  "solutionType": 2,
  "pageNum": 1,
  "pageSize": 20,
  "i18n": { "language": "zh-CN", "timezone": 8 },
  "extendInfo": {
    "refer": "/bos/products/<productCode>/{bosId}/{key}/...",
    "source": 80
  }
}
```

**怎么拿到这份骨架？** 不要手写——打开目标页面，监听第一个业务 XHR，把 `postData()` 存下来当模板。
每个接口的差异只在 `pageNum/pageSize/queryParameter/xxxList` 这几项。

### 响应格式

```json
{ "errcode": "0", "errmsg": "处理成功", "data": { }, "globalTicket": "...", "monitorTrackId": "..." }
```

⚠️ `errcode` **类型不统一**：商品域是字符串 `"0"`，素材域是数字 `0`。判断必须写 `err === 0 || err === '0'`。

## 4. 目录与产物约定

```
.scan/
├── profile/            playwright 持久化登录态（含 cookie，勿提交）
├── out/                接口原始响应、中间 JSON
├── backup/             备份产物（商品/素材全量 + CSV）
└── shots/              截图存档
```

备份文件名一律 `<对象>_<ISO时间戳>.json/.csv`，便于回滚时定位"哪一次"。
