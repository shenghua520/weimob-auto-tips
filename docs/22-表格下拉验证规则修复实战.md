# 22 · 表格「数据验证(下拉)」规则修复实战

> 场景：腾讯文档「九大分组商品录入表」的二级分组下拉坏了 —— 体育用品表的下拉弹的是**少儿穿戴**的选项，
> 且各表下拉里混进了**空行和表头文字**。本文记录根因、可行修法、以及为什么 MCP 走不通只能上浏览器。

---

## 一、问题现象（先分清「下拉坏了」的两种含义）

打开「数据 → 数据验证」对话框，看到的规则长这样：

| 分表 | K 列（二级分组）下拉实际引用 | 正确值 | 后果 |
|---|---|---|---|
| 学习文具 | `OFFSET(字段说明!$C$43,…)` | 同 | ✅ 正常 |
| **体育用品** | **`OFFSET(字段说明!$F$41,…)`** | **`$D$43`** | ❌ 弹少儿穿戴的选项 |
| 少儿护理 / 少儿穿戴 / 少儿食品 | `$E$43` / `$F$43` / `$G$43` | 同 | ✅ 但第 8 行是碎片 |

**两类坏法**：

1. **引错列**：`$F` = 二级分组·少儿穿戴，体育用品本该引 `$D`（二级分组·体育用品）。
2. **行起点错位**：写成 `$X$41`（正确 `$X$43`）。
   字段说明第 42 行是清单表头、43 行起是选项，起点用 41 会把**第 41 行空行 + 第 42 行表头文字**一起塞进下拉；
   配合 `COUNTA($X$41:$X$140)`，下拉里就会多出「空行 + 二级分组·某某」这种垃圾项。

第 8 行的碎片更隐蔽：`K8` 单独一条 `OFFSET(字段说明!$E$44,…)` —— 起点 44 会**跳过第一个选项**，
所以第 8 行的下拉比同列其它行少一项。全表 12 张共 12 条这类错位。

---

## 二、关键取证方法：验证规则只能从导出的 xlsx 读

**MCP 的 `get_cell_data` / CSV 快照都读不到数据验证规则**（那是 sheet 的元数据，不在单元格值里）。
唯一权威来源是**导出的 xlsx 里 `xl/worksheets/sheetN.xml` 的 `<dataValidation>` 原始 XML**：

```python
dvs = re.findall(r'<dataValidation\b.*?(?:/>|</dataValidation>)', xml, re.S)
for d in dvs:
    sq = re.search(r'sqref="([^"]*)"', d).group(1)   # 作用范围
    f1 = re.search(r'<formula1>(.*?)</formula1>', d, re.S).group(1)  # 公式
```

导出用 `tencent-docs` 的 `manage.export_file` + `manage.export_progress` 轮询拿 `file_url`，
本表导出约 **303MB**（图片极多），必须**只解压需要的 XML、不要整包处理**。

### ⚠️ 解析坑：别用「跨 cell 的宽松正则」去读单元格值

自闭合的空单元格 `<c r="D3"/>` 会让「`<c ...>(.*?)</c>`」这种贪婪/跨 cell 匹配串行，
我据此一度得出「字段说明的清单列大面积串列污染」的错误结论。
正解是**按 `<c r="列行号">` 精确取位**：

```python
for c in re.finditer(r'<c r="([A-Z]+)(\d+)"([^>]*?)(?:/>|>(.*?)</c>)', xml, re.S):
    col, row, attrs, body = c.group(1), int(c.group(2)), c.group(3), c.group(4) or ''
```

## 三、为什么 MCP 写不了（两条路都堵死）

### 路线 1：MCP `set_data_validation` —— 类型限制

```python
td.call_tool('sheet-mcp','set_data_validation', {
    'file_id': FID, 'sheet_id': SID, 'ranges': ['AZ100:AZ101'],
    'type': 'LIST', 'formula1': 'OFFSET(字段说明!$D$43,0,0,COUNTA(字段说明!$D$43:$D$142),1)'})
# → error: op/formula1/formula2 are only allowed when type ∈ {WHOLE, DECIMAL, DATE, TIME, TEXT_LENGTH}
```

`LIST` 类型**只接受静态 `select_options`**，引用式公式一律拒。
列模式（`col_indexes`）同样拒。**MCP 侧无解。**

### 路线 2：腾讯文档 UI「数据验证」对话框 —— 公式校验

浏览器里手动改公式时，**原封不动的旧公式也报错**：

```
⚠ 输入的单元格范围无效，请重新输入
```

关键实验（用来区分「公式文本错」与「对话框不认 OFFSET」）：

| 试的公式 | 结果 |
|---|---|
| 原式 `=OFFSET(字段说明!$F$41,0,0,COUNTA(字段说明!$F$41:$F$140),1)` | ❌ 同样报错 |
| 换成 `=OFFSET(字段说明!$D$43,…$D$142…)` | ❌ 同样报错 |
| **换成区域引用 `=字段说明!$D$43:$D$142`** | ✅ **保存成功** |

**结论：新版「设置数据验证」对话框的公式框只接受真正的区域引用，不接受 OFFSET 这类函数式动态引用**
（公式框的 placeholder 也印证了这点：「选项用英文逗号隔开，如1,2,3」——它按"手动输入"模式写的校验）。

### ✅ 可行写法：区域引用，动态性等价

```
=字段说明!$D$43:$D$142
```

- 依然是**引用「字段说明」清单列**，改字段说明即同步（保住原设计）；
- 引用区间尾部是空单元格，但腾讯文档下拉会**自动跳过空单元格**，实测下拉里没有空白项；
- 比 OFFSET 更健壮：清单列中间出现空洞也不会截断。

## 四、UI 操作要点（踩过的坑）

1. **勾选「对于同样设置的单元格应用这些更改」不等于全范围覆盖**：
   我选了 `K2:K2001` 整列去改，结果导出后发现 **`K8` 的碎片规则原封不动**（因为 K8 的设置与其它格不同，
   不在「同样设置」的范围内）。**碎片必须逐格单独选中、单独设置。**
2. **浏览器会话要有写权限**：内置浏览器初始可能对该文档是「只能查看」（对照：MCP 走的账号是所有者「阿白」，有写权限）。
   用户在浏览器里登录后即可写。
3. **大表渲染会让截图/点击超时**（本表 303MB）：`tab_screenshot` / `dom_cua_click` 偶发
   `CDP Input.dispatchMouseEvent timed out` / `provider invocation timed out`。
   对策：改用 `dom_cua_get_visible_dom`（只读，快）+ `dom_cua_click(node_id)`，避开截图依赖；
   实在卡住就 `tab_reload` 或重开 tab。
4. **「数据验证」是带下拉箭头的组合按钮**：点图标主体 → 打开对话框；点箭头 → 弹出「下拉选项/复选框/评星/…」类型菜单。
   DOM 里 `aria-label="数据验证"` 的按钮用坐标点更稳（图标右侧约 x=+20 处才是箭头）。
5. **标签栏会横向滚动**：「线下铺货」不在默认可见区，需要点标签栏左箭头滚到最左。
6. **名称框导航**：左上角输入框输入 `E228:E293` + 回车 → 选中并跳转。必须先 `ctrl+a` 再输入。

## 七、Takeaway

1. **表格的下拉规则是 sheet 元数据，MCP 读不到、也写不了**；要查要改只能走「导出 xlsx 读 XML」+「浏览器 UI」。
2. **引用式下拉在新版腾讯文档对话框里只能写成区域引用**（`=字段说明!$D$43:$D$142`），
   OFFSET 公式过不了校验；区域引用同样是动态的，空单元格会被下拉自动跳过。
3. **下拉坏掉通常是"列引错 + 行起点错位"两个 bug 叠加**，症状是下拉里混进别的表的选项和表头文字。
4. **整列重设不会覆盖"设置不同"的单元格** —— 同一列里若有单格碎片，必须逐格单独修。
5. **复核要做四层**：规则层（起点/结束行）、映射层（引的列对不对）、清单层（内容对不对）、
   数据层（改规则有没有误伤单元格值），基准要取"本轮开始前"而不是"最初快照"。
