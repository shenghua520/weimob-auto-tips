# 01 · 鉴权与错误码

## 1. 登录流程

微盟后台挂在 `master.weimob.com`，未登录会被重定向到：

```
https://account.weimob.com/codeLogin?back=<URL-encoded 回跳地址>
```

登录页有两种模式：

| 模式 | 元素 | 说明 |
|---|---|---|
| 验证码登录（默认） | `请输入手机号码` + `验证码` + `获取验证码` | 需短信，自动化成本高 |
| **密码登录** | `请输入手机号码` + `请输入密码`（`input[type=password]`） | 点顶部「密码登录」tab 切换 |

### 自动化登录要点

```js
// 1. 打开任意后台地址 → 自动跳到 login
await page.goto(TARGET);            // 等 domcontentloaded
await page.waitForTimeout(4000);

// 2. 切「密码登录」（默认是验证码模式）
await page.getByText('密码登录', { exact: true }).click();

// 3. 两个 input.ant-input：手机号 + 密码
const ins = page.locator('input.ant-input');
await ins.nth(0).fill('<ACCOUNT>');
await ins.nth(1).fill('<PASSWORD>');

// 4. 勾选协议（若有），再点登录
const cb = page.locator('input.ant-checkbox-input');
if (await cb.count() && !(await cb.first().isChecked())) await cb.first().check({ force: true });
await page.getByRole('button', { name: /登\s*录/ }).first().click();
```

登录成功后回跳到 `master.weimob.com/bos/products/...`，标题形如 `概况 - 店铺 | <商户名> - 微盟`。

**持久化**：用 `launchPersistentContext(PROFILE)`，登录态存进目录，后续免登录。
实测该 profile 约 127MB（含浏览器缓存），能长期复用。

## 2. 请求头清单

| 头 | 必需 | 说明 |
|---|---|---|
| `authorization` | ✅ | 登录票据。**光有 Cookie 不够**，缺了直接 `fail auth` |
| `apiclient` | ✅ | 客户端标识（如 `weimob-bos`），固定值 |
| `weimob-bosid` | ✅ | 商户 ID，与 body 里 `basicInfo.bosId` 一致 |
| `content-type` | ✅ | `application/json` |
| `referer` | 建议 | 部分接口校验来源页，缺失可能 403 |
| `apipath` | 按需 | 仅 iPaaS 网关 `.../weimob/saas/admin` 需要，用来区分功能 |

### 怎么拿到 value

打开目标页面 → 监听第一个业务 XHR → 抄 `request.headers()`：

```js
let H = null;
page.on('request', r => { if (r.url().includes('queryGoodsListWithPageForManagement')) H = r.headers(); });

const KEEP = ['authorization', 'apiclient', 'weimob-bosid', 'content-type', 'referer'];
const headers = {}; KEEP.forEach(k => { if (H[k]) headers[k] = H[k]; });
```

> `authorization` 有时效，但通常随 Cookie 一起刷新；只要页面还能正常用，抄下来的就是有效的。

## 3. 错误码与处置

| errcode | 原文 | 含义 | 处置 |
|---|---|---|---|
| `0` / `"0"` | 处理成功 | 成功 | — |
| `1041` | `fail auth` | 缺 `authorization` 或已过期 | 重抄请求头；仍失败则重新登录 |
| `11010000002` | `updateUid不能为空, 组织架构Id不能为空, 素材类型不能为空` | 删除类接口必填字段缺失 | 逐项补：`updateUid`（用素材的 `createUid`）、`vid`、`materialType` |
| HTTP `404` | `{"status":404,"path":"..."}` | 接口名猜错 | 见下节「接口名怎么找」 |

### 两个非错误但会坑人的返回

| 现象 | 真相 |
|---|---|
| `totalCount=0` + `pageList=[]`，errmsg 仍是"处理成功" | **pageSize 超过上限被静默忽略**。商品接口上限 20，传 200 就返空 |
| 删除类接口返回 `result:true` + `taskId` | **异步任务**，不代表数据已变。必须回读 |

## 4. 接口名怎么找（别猜）

凑巧猜对是运气，正确做法有三种，按可靠性排序：

1. **在页面上做一次真实操作，抓请求** —— 最准。哪怕只删 1 条，抓到的就是完整 body 模板
2. **读前端 JS bundle** —— 响应里的 `codeList`（`queryCodeListByProductId`）会返回该产品线所有权限码，
   形如 `mpmaterial#mpmaterial.material.tuwenEdit`，能反推接口命名规律
3. **按命名规律试** —— `material/center/material/` + `deleteMaterial` / `batchDelete` / `remove` 各试一次，
   404 就是不存在，能跑通说明对了。**但只有在第 1 种不可行时才用**

> 实测：`batchDeleteMaterial`、`removeMaterial`、`material/delete` 全 404，
> 真名是 `material/center/material/deleteMaterial`。猜中概率并不高。

## 5. 安全红线

- 不要在代码里硬编码 `authorization`，用环境变量或 `config.local.js`（已 gitignore）
- 不要把整个 `profile/` 目录提交到 Git —— 里面是完整登录态
- 生产商户后台一律先只读巡查，写操作前必须快照
