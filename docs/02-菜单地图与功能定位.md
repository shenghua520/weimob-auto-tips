# 02 · 菜单地图与功能定位

> 目标：不点页面，一次性拿到"这个后台到底有哪些功能、分别在哪"。
> 结果：13 个一级菜单组、**428 个功能入口**、最深 4 级。

## 1. 为什么不能点侧边栏

微盟后台是 SPA + 微前端，侧边栏**只渲染当前展开层**。用脚本逐个点击统计会漏：

- 实测漏了「员工」模块 3 个二级菜单里的 2 个（侧边栏只显示到二级，三级要点开才有）
- 「商城」模块有 6 个一级组 90 个节点，靠点要翻 5 层

**点一遍 ≠ 全量。接口才是全量。**

## 2. 权威接口：queryCacheableMenus

```
POST https://master.weimob.com/api3/merchant/backstage/service/share/queryCacheableMenus
```

- 首屏加载时自动发出，**每切换一个产品线发一次**
- 响应体很大（最大实测 172KB），`data.menus` 就是该产品线的完整菜单树

### 响应结构

```jsonc
{
  "errcode": "0",
  "data": {
    "menus": [ /* 树 */ ],
    "codeList": ["mpmaterial#mpmaterial.material.tuwenEdit", ...],  // 权限码，可反推接口
    "productId": null
  }
}
```

### 节点字段（全部实测存在）

| 字段 | 说明 |
|---|---|
| `name` | 菜单名（中文） |
| `url` | **完整跳转地址**（含 productCode / bosId / key），直接可用 |
| `authCode` | 权限码，如 `home#storeHome.index` |
| `level` | 层级，1-4 |
| `children` | 子节点数组，叶子为 `null` |
| `isHide` | 是否隐藏（实测全为 0） |
| `privilegeId` / `parentPrivilegeId` | 权限点 ID |
| `vidType` | 适用组织类型 |
| `orderNum` | 排序 |

## 3. 采集脚本

见 `scripts/01-sniff-menu.js`。核心是遍历顶部导航，每个模块触发一次接口：

```js
// 顶部导航的 14 个入口（含「应用」）
const mods = await page.evaluate(() => Array.from(
  document.querySelectorAll('.weimob-components-nav-list-index-navList li a')
).map(a => ({ name: a.innerText.trim(), href: a.getAttribute('href') })));

for (const m of mods) {
  await page.goto(m.href);
  await page.waitForTimeout(3500);   // 等接口回来
}
```

用 `page.on('response')` 收集所有 `queryCacheableMenus` 响应，按 `JSON.stringify(menus)` 的 md5 去重。

> **去重很关键**：`店铺` / `推广` / `数据` 三个模块共用 `home` 产品线，
> 抓 14 次会拿到 3 份完全相同的树（实测 15 条里 3 条重复）。

## 4. 模块归属怎么判

菜单树是**按产品线**给的，13 棵树对应 13 个业务模块。判断某棵树属于谁：

**看它的根节点 URL 里的 productCode**，而不是看名字。

```js
const firstUrl = ns => {
  for (const n of ns) {
    if (n.url) return n.url;
    if (n.children) { const r = firstUrl(n.children); if (r) return r; }
  }
  return '';
};
const code = (firstUrl(menus).match(/bos\/products\/([^/]+)\//) || [])[1];
```

映射表：

```js
const ROOT2MODULE = {
  home: '店铺', mpcms: '店铺',
  ecOrder: '商城', ecGoods: '商城', ecPlatform: '商城',
  onecrm: 'CRM', staff: '员工',
  wosheading: '供应链', wosheadingsop: '店务', wosheadingpos: '收银',
  ecTweeter: '分销', mkmarketing: '营销', sente: '数据', im: '客服',
  mav2: 'CDP', mkPromotionLive: '内容',
};
```

⚠️ **踩坑**：一开始用"树里出现最多的 productCode"判定，结果 `home` 树里因为含订单/商品菜单，
被判成了「商城」，导致店铺树和商城树合并成一个 201 节点的怪物。
**必须用根节点（第一个有 url 的节点）的 code。**

## 6. 产物：可检索地图

`scripts/02-build-feature-map.js` 生成两个文件：

- `微盟后台功能地图.html` —— 单文件离线版，支持按关键词搜索（积分/储值/对账/发票…）、逐级展开、每条带**直达链接**
- `微盟后台功能地图.md` —— 文本版，含「我想做什么 → 去哪」速查表 + 完整树（带 URL）

### 容易找错的几个（实测）

| 想干什么 | 不在哪 | 实际在哪 |
|---|---|---|
| 积分 / 储值 | ❌ 不在「营销」 | `CRM > 资产管理` |
| 员工账号权限 | ❌ 不在「员工」模块 | `店铺 > 店铺设置 > 账号权限`（「员工」只管导购和排班） |
| 运费模板 | ❌ 菜单里没有"运费"字样 | `商城 > 商城设置 > 配送设置 > 商家配送` → 页内页签「运费模板管理」 |
| 开屏广告 | — | `店铺 > 店铺装修 > 开屏推广` |
