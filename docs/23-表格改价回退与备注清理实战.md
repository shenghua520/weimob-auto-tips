# 23 · 表格改价回退与备注清理实战（学习文具 49 行）

## 一、背景

上一轮按「学习文具表价格多有修改」把表格基线价同步到微盟（脚本 138/139，457 售价 + 195 积分写入）。
用户随后发现**表格本身出了问题**，自己把其中 **49 行非晨光联盟商品**（1688 36 行 + 旺店通 13 行）
的价格改回原来的正确价，要求微盟也跟回去。

## 二、定位：先分清「我写的状态改动」与「用户改的价格」

读现网表格与本轮基线逐格对比，85 行变动要拆开：

| 类别 | 行数 | 谁改的 | 处理 |
|---|---|---|---|
| 纯 D 列状态「正常售卖→下架」 | 36 行 | 我（上一轮 137） | 保留 |
| Q/R/S/T 价格列 | **49 行** | 用户（本轮改回原价） | 微盟要跟回去 |

49 行全是 1688 / 旺店通，无一行晨光联盟；列分布：售价 49、组合价格 49、组合健康豆 49、纯豆兑换数 4。

## 三、关键坑：plan 的 row_excel 有 off-by-one

上一轮 133 生成的 `aligned.row_excel` 比真实 Excel 行号小 1（seq29 指向 66，实际 67）。
用它直接映射现网表格价会取到上一商品的行（取到 seq28 的 16.4 而不是 seq29 的 7.1），
导致 66 处里有 38 处"对不上"。

**解法**：不要用 `row_excel`，改用 **(序号, 规格值组合) → 现网表格价** 建映射，
再按 `sku_key` 对应到 priceWrites。这样绕开了行号基准问题，且规格+序号本身唯一。

## 四、方向确认：表格是权威，微盟跟表格

上一轮 138 台账的 `rollback` 字段恰好记录了写入前微盟原价，与表格改回后的价高度一致
（seq29=7.1、seq30=13.8、seq32=6.7、seq33=178/318/38 全 MATCH）。
seq31 有 4 处微盟原价（20.1/21.4）比表格现价（20.2/21.5）差 0.1——**以表格现价为准**，
因为用户明确说表格改回的是正确价。

## 五、执行（七步法）

1. **备份**：143 计划读现网微盟当前价作 rollback（10 商品 / 66 SKU）。
2. **计划**：目标价 = 表格现网价；seq21/28 微盟零命中跳过（与上一轮一致）；seq31 三行未对齐保持跳过。
3. **小样**（144）：seq29 原版 4 SKU，写→回读→三查（目标生效 / 非目标零变化 / costPrice 零变化）→ 自动回滚，PASS。
4. **批量**（145）：10 商品 / 66 SKU，逐单回读，失败阈值 3，零失败。
5. **四轮复核**（146）：
   - R1 目标级 66 SKU 现价 == 表格价，差异 0
   - R2 连带级 costPrice 差异 0
   - R3 范围外级 目标外 SKU 售价变化 0
   - R4 表格级 49 行价格未被误写，差异 0
6. **全量复核**（141 改造）：用 143 计划覆盖 133 的目标价后重跑——
   1037 商品 ID 零增减、范围外 890 个 STATIC 零变化、目标 SKU 售价 0 不符、连带 0 变化、台账 147 ID 全在计划内。VERDICT PASS。

先把误清的 U77 用正确格式复原，再重跑小样 PASS → 批量清 3 格 → 独立回读：3 格全空、144/145 保留、历史备注 51/115 未动。

## 七、Takeaway

1. **表格↔微盟同步要先确认谁权威**：本轮是表格改、微盟跟；不能因为"上次是表格跟微盟"就反向。
2. **对比表变动要拆开「我的写」与「用户的改」**：85 行里 36 是我写的状态、49 是用户改的价格，混在一起会误判范围。
3. **行号 off-by-one 的绕行**：plan 里的 `row_excel` 不可信时，用业务键（序号+规格）重新建映射，比重修行号更安全。
4. **`rollback` 是金矿**：写入台账里记录的写前值，回退场景可直接复用，但要人工确认哪个是权威价。
5. **清空用 `clear_range_cells`，写回文本用 `string_value`**：`value` 字段会被静默忽略，导致回滚校验 FAIL（实际是工具参数错，不是写入失败）。
6. **清备注也按来源/范围拆**：用户说"非晨光联盟的"就是只清自己加的那部分，晨光联盟的历史备注要留。
